# Wi-Fi Observation Model

Status: Accepted for Phase 0

This document defines the first platform-independent model direction for Wi-Fi
observations and field snapshots. It is a design contract, not Kotlin source.

## Goals

- Preserve the information Android exposes without inventing precision.
- Keep Android framework types out of domain and export models.
- Preserve SSID display text and raw SSID bytes when available.
- Keep BSSID, MLO link, and MLD identity distinct.
- Keep snapshots neutral enough for future Ehecatl interoperability.

## Identity Model

Yeyecatl uses separate identities for separate concepts:

| Concept | Meaning | Example source |
|---|---|---|
| Observation identity | One normalized record captured by Yeyecatl at one capture time. | Generated by Yeyecatl. |
| BSS/BSSID identity | Identity reported for a basic service set. | `ScanResult.BSSID`. |
| MLO link identity | Link identifier for a Wi-Fi 7 MLO link. | `ScanResult.getApMloLinkId()`. |
| MLD identity | Multi-link device MAC address for a Wi-Fi 7 AP. | `ScanResult.getApMldMacAddress()`. |
| Snapshot identity | One user-visible capture set. | Generated by Yeyecatl. |

BSSID is not a guaranteed physical access point identity. Do not merge
observations only because SSID display text or BSSID-like values appear related.

## SSID Representation

SSID has two representations:

- display text: what can be safely shown to the user;
- raw bytes: the underlying SSID byte sequence when Android exposes it.

The implementation should avoid a raw `ByteArray` property in a data class
unless it is wrapped with content-based equality. Non-UTF-8 SSIDs must not be
silently destroyed by a display-string-only model.

Conceptual type:

```kotlin
data class Ssid(
    val displayText: String?,
    val rawBytes: SsidBytes?,
    val isHidden: Boolean
)

data class SsidBytes(
    val bytes: ByteArray
) {
    // Implement content-based equality and hashing.
}
```

## Access Point Observation

Conceptual type:

```kotlin
data class WifiAccessPointObservation(
    val id: ObservationId,
    val observedAt: Instant,
    val ageAtCapture: Duration?,
    val ssid: Ssid?,
    val bssid: Bssid?,
    val rssiDbm: Int?,
    val primaryFrequencyMhz: Int?,
    val centerFreq0Mhz: Int?,
    val centerFreq1Mhz: Int?,
    val channel: WifiChannel?,
    val band: WifiBand,
    val channelWidth: ChannelWidth,
    val securityTypes: Set<SecurityType>,
    val capabilitiesRaw: String?,
    val wifiStandard: WifiStandard,
    val mloLinkId: MloLinkId?,
    val mldMacAddress: MldMacAddress?,
    val platformMetadata: ObservationPlatformMetadata?
)
```

Value object direction:

```kotlin
@JvmInline value class ObservationId(val value: String)
@JvmInline value class SnapshotId(val value: String)
@JvmInline value class Bssid(val value: String)
@JvmInline value class MldMacAddress(val value: String)
@JvmInline value class MloLinkId(val value: Int)
@JvmInline value class WifiChannel(val value: Int)
```

The string-backed MAC value objects are placeholders for validated textual MAC
representations. They should not be interchangeable types.

```kotlin

    WPA3_SAE,
    OWE,
    WAPI_PSK,
    WAPI_CERT,
    WPA3_ENTERPRISE,

    LEGACY,
    WIFI_4,
    WIFI_5,
```

Unknown values are first-class. Yeyecatl must not fill unknown platform data
with invented defaults.

## Platform Metadata

Portable observations expose `ageAtCapture`, not Android boot-relative
timestamps. Android raw metadata may be retained in a platform extension:

```kotlin
sealed interface ObservationPlatformMetadata

data class AndroidObservationMetadata(
    val scanResultTimestampMicrosSinceBoot: Long?,
    val sourceApiLevel: Int,
    val sourceFields: Set<String>
) : ObservationPlatformMetadata
```

Export code should decide whether to include platform metadata. The core schema
must remain useful without it.

## Platform-Neutral Field Snapshot

Conceptual type:

```kotlin
data class WifiFieldSnapshot(
    val snapshotId: SnapshotId,
    val schemaVersion: Int,
    val capturedAt: Instant,
    val source: ObservationSource,
    val observations: List<WifiAccessPointObservation>,
    val note: String? = null
)

data class ObservationSource(
    val collectorName: String,
    val collectorVersion: String?,
    val platform: PlatformKind,
    val capabilities: Set<CollectorCapability>
)
```

`ObservationSource` identifies the collector at a neutral level. Android device
details belong in optional platform metadata, not in the required snapshot
schema. This keeps later Ehecatl comparison feasible.

## Repository and Adapter Boundaries

```text
Compose UI
    |
ViewModel / UI state
    |
WifiObservationRepository
    |
AndroidWifiScanner
    |
WifiManager / Android permissions / Location Services
```

Interfaces to introduce in Phase 1:

```kotlin
interface WifiObservationRepository {
    val scanState: StateFlow<ScanState>
    suspend fun requestForegroundScan()
    suspend fun latestSnapshot(): WifiFieldSnapshot?
}

interface WifiCapabilityProvider {
    suspend fun currentCapabilities(): WifiCollectorCapabilities
}
```

Keep these boundaries minimal. Do not add a database, DI framework, or separate
Gradle modules merely because this model exists.

## Required Tests

Phase 1 deterministic tests should cover:

- frequency to band conversion;
- frequency to channel conversion;
- unknown and out-of-range frequencies;
- channel-width normalization;
- 80+80 center frequency preservation;
- multiple security types;
- hidden SSID and raw-byte preservation;
- duplicate SSID across distinct BSSIDs.
